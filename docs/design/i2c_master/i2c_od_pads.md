# `i2c_od_pads` — Open-Drain Pads + Synchronization Layer

## Purpose
Bridge between:
- **wire-level I²C bus** (`scl`, `sda`) which is *asynchronous* to `clk` and obeys open-drain rules, and
- **core clock domain** signals (`scl_sync`, `sda_sync`) that are safe to use inside synchronous RTL.

This block is the “physical interface model” for I²C:
- drives the bus using open-drain semantics (`*_pull`)
- samples the bus and provides synchronized views (`*_sync`)

---

## Interface (typical)

### Inputs (from core)
- `clk`, `rst_n`
- `scl_pull` — **1 pulls SCL low**, 0 releases
- `sda_pull` — **1 pulls SDA low**, 0 releases

### Outputs (to core)
- `scl_sync` — SCL sampled and synchronized into `clk` domain
- `sda_sync` — SDA sampled and synchronized into `clk` domain

### Bus nets (wire-level)
- `scl` — open-drain bus net (tri-state / wired-AND)
- `sda` — open-drain bus net (tri-state / wired-AND)

> In SV you usually model these as `tri1` (pulled-up by default) plus conditional `0` drive from master/slave pullers.

---

## Contract

### Assumptions
- The bus is open-drain:
  - any device can **pull low**
  - nobody actively drives high
  - a pull-up makes the released line read as 1
- `scl_pull/sda_pull` are synchronous to `clk` (generated by your core FSMs).
- External devices (slave model) may pull SCL/SDA low at arbitrary times.

### Guarantees

#### Open-drain driving
- If `*_pull == 1` then the pad layer drives the corresponding bus net low.
- If `*_pull == 0` then the pad layer **releases** the net (high-Z).
- The actual bus value equals the wired-AND result of all participants:
  - if **any** participant pulls low → bus reads 0
  - else → bus reads 1 (via pull-up)

#### Synchronized sampling
- `scl_sync` and `sda_sync` are safe to use in `clk` domain:
  - they change only on clock edges
  - they do not glitch (in the digital model)
- `*_sync` is produced by a **2-flip-flop synchronizer** (recommended):
  - this reduces metastability risk
  - it introduces a **latency of ~2 clocks**

> Important: the synchronizer means `*_sync` is a delayed view of the bus wires. This is intentional.

---

## Latency and “what it means” in time

Let `sda_wire` be the wire-level value, and `sda_sync` the core-domain value after 2FF sync.

- If the wire changes just before a clock edge, it may be captured at the next edge.
- In the ideal digital view (ignoring metastability), you can often think:
  - `sda_sync(t) ≈ sda_wire(t−2 cycles)`

### Key implication
If your testbench changes the slave pull signal “right now”, the core will see that change on `sda_sync` **about two clock edges later**.

This is not an I²C rule; it’s a CDC + sampling rule.

---

## Reset behavior
On `!rst_n`:
- `scl_sync`, `sda_sync` reset to a known value (often 0)
- This reset value is not meant to represent the actual bus level — it’s just a safe internal initialization.

> For I²C semantics, your *core* should treat “idle” as releasing the bus (`*_pull=0`) regardless of sync reset value.

---

## Composition rules (how other bricks should use it)

### Who consumes `*_sync`?
Any module that makes protocol decisions based on bus level, e.g.:
- stretching detection (`scl_sync`)
- read sampling (`sda_sync`)
- arbitration / multi-master (future)

### Who drives `*_pull`?
Your protocol FSMs:
- SCL controller (`i2c_scl_req` / higher-level bit controller)
- SDA controller (`i2c_bit_prim`, start/stop generator, etc.)

### What must NOT happen
- A module must not assume that changing a pull immediately changes `*_sync`.
  - `*_sync` is intentionally delayed.

---

## Testbench implications (this is usually where confusion happens)

There are two valid test styles:

### A) Unit tests (core-only)
Don’t instantiate `i2c_od_pads`; drive `scl_sync/sda_sync` directly.
- Pros: simple, deterministic, no CDC latency concerns
- Cons: less realistic

### B) System tests (realistic bus)
Instantiate `i2c_od_pads` + tri-state bus nets + slave open-drain drivers.
- Pros: closest to hardware
- Cons: you must account for synchronizer delay

**Rule of thumb for system tests:**
After changing the slave’s pull signals, wait **at least 2 rising edges** before expecting the DUT to “see” it on `*_sync`.

## Suggested formal / assertions (optional)
These are local properties you can prove or assume:

- `*_sync` changes only on `posedge clk` (except reset)
- If wire is stable for >=2 cycles, then `*_sync` eventually equals wire (bounded liveness; environment-dependent)
- Pad drive correctness: if `*_pull==1` then wire reads 0 (assuming no other driver forces illegal high)

---

## Practical notes
- In real silicon, the synchronizer is mandatory if you sample external SCL/SDA.
- For timing of I²C, your controller should decide sampling points based on internal time (`tick`) and *observed* `scl_sync`/`sda_sync`, not raw wires.
- If you later need multi-master arbitration, you will extend this layer with “what I drove vs what I read” checks.
